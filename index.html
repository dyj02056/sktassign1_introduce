01 / EXECUTE

PROBLEM / 불확실한 시작

조별 프로젝트 초기, 명확한 방향과 구체적 요구사항이 부족해 기획의 불확실성이 높았습니다. 말이나 문서만으로는 팀의 싱크를 맞추기 어려워, 빠르게 확인할 수 있는 시각적 기준점이 필요했습니다.

ACTION / 먼저 만든 기준

사전에 학습한 웹 개발 기술로 가상 로그인 기능을 포함한 웹사이트를 단독으로 선제 구축했습니다. 초기 프로토타입을 즉시 배포·공유해 추상적 아이디어를 눈에 보이는 결과물로 바꿨습니다.

RESULT / 협업 가속

모호했던 요구사항을 조기에 구체화하고 프로젝트 방향을 빠르게 확립했습니다. 기술적·시각적 기준을 미리 다져 이후 협업 속도를 높이고 원활한 진행을 주도했습니다.

02 / WRITE

JSW.log

기록하는

PROBLEM / 반복되는 변수

구현·배포 단계에는 환경 차이, 설정 누락, 예상 밖 버그가 동시다발적으로 발생합니다. 원인과 수정 이력이 관리되지 않으면 같은 실수와 정보 격차가 반복되므로 기록·공유 프로세스가 필요했습니다.

ACTION / 로그를 자산으로

발생한 에러와 개선 사항을 사소한 것까지 실시간으로 상세 기록했습니다. 로그로 근본 원인을 분석해 코드를 보완하고, 수정 전후 결과와 적용 사항을 명확히 업데이트해 팀 자료실에 즉시 공유했습니다.

RESULT / 투명한 피드백 루프

시행착오 시간을 단축하고 같은 오류의 재발을 차단했습니다. 해결 과정과 피드백 루프를 축적해 안정적 배포와 완성도를 높였으며, 프로젝트 리스크를 투명하게 관리했습니다.

03 / PREVENT

JSW.lint

예방하는

PROBLEM / 멈출 수 있는 서버

Supabase 무료 플랜은 7일 동안 DB 활동이 없으면 서버가 자동 일시 중지됩니다. 시연·테스트 중 장애를 막고 팀원이 인프라 관리에 신경 쓰지 않도록 자동 유지보수가 필요했습니다.

ACTION / 비용 없는 자동화

유료 모니터링 도구 대신 협업 중인 GitHub Actions를 사용했습니다. schedule 트리거와 Cron Expression으로 매일 가벼운 Health Check API 호출을 실행하는 자동화 워크플로우를 작성했습니다.

RESULT / 상시 활성 환경

개발팀이 수동으로 쿼리를 실행하지 않아도 Supabase 서버를 안정적으로 Active 상태로 유지할 수 있게 됐습니다. 운영 리스크를 코드로 예방한 무중단 개발 환경입니다.
